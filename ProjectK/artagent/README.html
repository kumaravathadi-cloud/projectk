📌 Overview

The ARTAgent framework is a modular, enterprise-grade voice agent orchestration system built on Azure services. It enables building sophisticated multi-agent voice systems with intelligent handoffs, tool integration, and real-time voice processing.

🚀 Key Innovation: The framework uses a three-layer modular architecture: Agents (YAML config + prompts), Tools (pluggable business logic), and Scenarios (multi-agent orchestration flows).

What ARTAgent Does

  • Manages multi-agent conversations with intelligent handoff routing
  • Integrates voice (ACS/VoiceLive) with AI orchestration (Azure OpenAI)
  • Provides scenario-based orchestration for banking, insurance, and more
  • Supports MCP (Model Context Protocol) for external tool integration
  • Delivers real-time voice with <2 agent handoff latency
  • Logs and manages call state via Redis + Cosmos DB

🤖 Agent System

What is an Agent?

An agent is a configured conversational entity with:

  • Identity: Name, description, greeting, role
  • Prompt: System message (Jinja2 template with variables)
  • Tools: List of tool names it can invoke
  • Voice Config: TTS/STT parameters
  • Model Config: LLM selection (default, cascade, voicelive)
  • Handoff Config: Routing rules to other agents

Agent Configuration

Each agent consists of three files in its folder:

1. agent.yaml - Agent Configuration

name: investment_advisor description: "Investment advisor for portfolio guidance" greeting: "Hello! I'm your investment advisor. How can I help with your portfolio today?" return_greeting: "Thank you for speaking with me. Your advisor will take it from here." handoff: trigger: handoff_investment_advisor is_entry_point: false model: name: gpt-4o temperature: 0.7 voice: voice_name: en-US-AvaNeural rate: 1.0 tool_names: - get_account_summary - get_investment_recommendations - handoff_concierge template_vars: context: "Investment advisory"

2. prompt.jinja - System Prompt Template

You are a professional investment advisor for {{ institution_name }}. Your role: {{ context }} Guidelines: - Provide personalized investment recommendations - Consider risk tolerance and investment timeline - Reference portfolio holdings - Suggest diversification opportunities Use only approved investment products. Do NOT provide tax or legal advice. Available tools: {{ available_tools }}

3. Optional: tools.py - Agent-Scoped Tools

# Agent-specific tool implementations async def get_investment_recommendations(args: dict) -> dict: account_id = args.get("account_id") # Custom investment recommendation logic return {"recommendations": [...]}

🔗 How Agents Are Connected

Connection Mechanism: Tool-Based Handoffs

Agents communicate via handoff tools. When an agent needs to transfer to another agent, it calls a handoff tool, which triggers a route to the target agent.

Handoff Configuration (HandoffConfig)

@dataclass class HandoffConfig: """Routes control from one agent to another""" trigger: str # Tool name (e.g., "handoff_fraud_agent") is_entry_point: bool # True for Concierge (starting agent) # In agent.yaml: handoff: trigger: handoff_investment_advisor is_entry_point: false

Scenario-Level Orchestration

Scenarios define which agents are available and their handoff relationships. This enables context-specific agent configurations (e.g., banking vs. insurance).

# scenarios/banking/scenario.yaml name: banking description: "Private banking customer service" agents: - BankingConcierge # Entry point - FraudAgent - InvestmentAdvisor - AuthAgent handoffs: - from: BankingConcierge to: FraudAgent tool: handoff_fraud_agent type: announced # Agent announces transfer - from: BankingConcierge to: InvestmentAdvisor tool: handoff_investment_advisor type: announced generic_handoff: enabled: true # Allow dynamic handoffs allowed_targets: [AuthAgent, FraudAgent]

Real-Time Tool Invocation

Azure OpenAI processes agent responses and invokes tools using function calling. The tool registry executes the tool and returns results.

# When agent says: "Let me transfer you to fraud detection" AZURE OPENAI (function calling) ↓ Detects: tool = "handoff_fraud_agent", args = {...} ↓ ORCHESTRATOR ↓ Calls: await tool_registry.execute_tool("handoff_fraud_agent", args) ↓ TOOL REGISTRY ↓ Looks up tool in registry ↓ Executes tool function ↓ Returns result with target agent info ↓ HANDOFF SERVICE ↓ Loads new agent from agentstore ↓ Switches orchestrator context ↓ Renders new greeting ↓ CALLER (receives): "Hello, fraud specialist here..."

Tool Registration & Discovery

Tools are registered at startup from multiple sources:

# In toolstore/registry.py def register_tool( name: str, schema: dict, # OpenAI function schema executor: Callable, # Async function to execute is_handoff: bool = False, # True for agent-to-agent routing tags: set = None, # e.g., {"banking", "fraud"} target_agent: str = None # If handoff tool ): """Register a tool globally""" _TOOL_REGISTRY[name] = ToolDefinition(...) # At startup (main.py): from apps.artagent.backend.registries.toolstore import initialize_tools initialize_tools() # Imports all tool modules, registers all tools

🚀 Quick Start Guide

1. Clone & Setup

git clone https://github.com/Azure-Samples/art-voice-agent-accelerator.git cd art-voice-agent-accelerator # Install Python dependencies pip install -r requirements.txt # Setup environment cp .env.sample .env # Edit .env with your Azure credentials

2. Select Orchestration Mode

# .env or export # Option 1: SpeechCascade (STT → LLM → TTS) export ACS_STREAMING_MODE=MEDIA # Option 2: VoiceLive (voice-to-voice, faster) export ACS_STREAMING_MODE=VOICE_LIVE

3. Run Backend

cd apps/artagent/backend python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000

4. Create Custom Agent

Create folder: registries/agentstore/my_agent/

# my_agent/agent.yaml name: my_agent description: "Custom specialized agent" greeting: "Hi, I'm here to help with X" handoff: trigger: handoff_my_agent is_entry_point: false model: name: gpt-4o temperature: 0.7 tool_names: - get_info - process_request - handoff_concierge
# my_agent/prompt.jinja You are {{ name }}, a specialized assistant. Your role: {{ context }} Available tools: {{ available_tools }}

Agent auto-discovered at startup! 🎉

5. Deploy to Azure

azd auth login azd up # ~25 minutes (infra + container deployment)

✅ Summary

ARTAgent is designed for rapid, enterprise-grade voice agent development:

  • 🏗️ Three-layer architecture: Agents (config), Tools (business logic), Scenarios (orchestration)
  • 🔗 Tool-based handoffs: Agents route via function calls to handoff tools
  • ⚡ Dual orchestrators: SpeechCascade (customizable) or VoiceLive (fast)
  • 🔌 MCP integration: Plug in external tools via Model Context Protocol
  • 📱 Multi-channel: Phone (ACS), web (WebRTC), browser demo
  • ☁️ Azure native: OpenAI, Speech Services, Cosmos DB, Redis, Container Apps
  • 📚 Production-ready: Monitoring, auth, compliance, scalability built-in
